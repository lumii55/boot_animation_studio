# BAS P15.7 — GIF autêntico para moderação privada (beta)
- O js/community-gif.js utiliza BASCommunityAnimation.buildFromZip() e frameAtTime(), lendo até dez quadros reais do bootanimation.zip. Captura em canvas local e codifica GIF89a em RGB332, com dimensões de no máximo 256 px e arquivo de no máximo 2 MiB.
- Depois da validação/quarentena original, o cliente tenta anexar o GIF pelo endpoint autenticado PUT /v1/publishing/drafts/:id/preview ou PUT /v1/publishing/revisions/:id/preview. Apenas a conta dona de uma versão ZIP pending pode anexar uma prévia, uma única vez. Alteração só de metadados reutiliza a prévia da versão base, caso exista.
- O Worker valida assinatura GIF89a e estrutura, dimensões, número de quadros, bytes e identificação. Não é possível provar, apenas pelo GIF gerado no cliente, que ele corresponde ao ZIP; por isso a administradora continua obrigada a conferir o ZIP em caso de dúvida. Não usar preview como autorização para aprovação automática.
- R2 guarda objetos unicamente sob previews/<animation>/<version>.gif, no bucket privado. Nenhuma URL pública é gerada; a quota global storage_budget contabiliza os bytes de GIF além dos ZIPs, e a quota de operações R2 também é usada. Falhas deixam a publicação ainda pendente, com fallback do painel privado.
- Eventos que ainda não têm GIF real são reprogramados na fila, em vez de enviá-los com imagem fictícia. Enviar DMs exige DISCORD_ADMIN_BOT_ENABLED=true, que permanece ausente. Nenhum Cron Trigger foi autorizado/ativado nesta revisão.
- Testes: node --test tests/*.cjs; node --test community-api/tests/*.mjs; python -m unittest discover -s community-api/tests -p 'test_*.py'. Inclui integração em SQLite com autenticação, ownership e quota, verificação do GIF por parser independente, proteção do endpoint do Discord.
- Falta: teste humano real no Vivaldi com ZIP e verificação de preview_key privada no staging; GIF em DM oficial, bot Discord, cron e relatórios. Proibir abertura do cadastro público ou merge em main até aceite explícito.
